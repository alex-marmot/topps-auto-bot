# Proposal

## Why

用户确认首版交付目标为可安装、流程实现完整并能由用户自行试用：安装后在专用浏览器人工登录，准备信用卡及必要收货资料，选择一个目标即可自动加购、结算、填卡和提交付款。继续独立实现并对齐参考操作，不要求开发者先用真实账号登录或真实成交，才能开放试用或认定开发交付完成。安装可用、真实风格页面处理及受控测试仍须完成。

## What Changes

- 参考仓库用于行为研究，仍不复制或逐句翻译源码、文档和资源；保留 Python + Tkinter、现有可复用配置与付款校验。本轮已加入 UC 启动适配、无整单截止、持续等待和可证失败重试；真实 UC/实站和 Windows 仍待验收。
- 浏览器基线恢复 Selenium + `undetected-chromedriver`（UC）、可见 Chrome、专用持久化 profile，以及参考项目的 `--disable-blink-features=AutomationControlled` 等启动配置。普通 Selenium 只作对照诊断，不静默替换所需方案；不把参数存在当作已通过 Cloudflare。
- Chrome/驱动按当前检测版本匹配，不写死参考的 146，也不把用户当前 156 当成长期常量。UC 驱动处理纳入私有暂存、同副本验证及原子启用；自动下载可取消、手动导入保留，不在执行时偷偷重新下载或修改驱动。
- `--no-sandbox` 保留为明确可识别的诊断兼容选项，默认启用沙箱，覆盖 UC 自身默认关闭沙箱的行为；仅凭 403 不默认关沙箱。记录最终参数与实测差异，不能将关闭沙箱宣称为 Cloudflare 通行条件。
- 主操作提供直链或关键词二选一、规格/数量、开始/停止与日志。直链解析后可直接确认本次目标；关键词列出候选由用户指定一个，不能遍历全部结果付款。预设用于复用，不要求先建预设再单独选中才能开始；账号、地址、卡和预算继续在设置中提前维护。
- 人工登录是首版默认流程，已登录会话可复用；不强制保存登录邮箱/密码或依赖自动登录成功。用户完成后检查可观察登录态，不能只凭固定等待或完成按钮直接付款。现有自动登录代码与配置可兼容保留，但不是启动或验收前置。
- 取消默认 60 秒及 1–600 秒整单提交窗口。对已选目标持续等待库存，直至可购、用户停止或明确异常；正常售罄等待与单次页面超时分开，UI 显示步骤、已运行时间及最近结果，不显示整单截止倒计时。旧窗口/定时字段仅兼容保留，不调度、不限制新任务，也不解除旧未决记录。
- 加购失败不再一律结束：仅可证明未发出，或官方明确暂时拒绝、无副作用、空车且无在途时，结束该次记录并间隔重试同一目标的完整数量。各尝试独立记录、无并发；已成功不再加购，部分数量/未知结果不得重试、补量或清车。付款仍至多提交一次，结果不明跨重启阻断。
- 保留 JS 操作兜底，但按动作区分：无购买副作用的控件或字段可在核实后用 JS 并回读；加购普通点击异常先核对结果，只在已证明未加购时才可新尝试。付款选择一种已验证的提交方式，不允许异常后另一种方式补点。
- 等待以页面状态为依据，保留参考节奏（售罄约 15 秒，暂不可用/可重试失败约 10 秒），等待可停止并尊重官网更长等待；固定时间流逝不是登录、加购或付款成功证据。
- 单目标、完整数量、USD 单价及整单上限、空车前置、默认配送核对、敏感配置隔离和付款结果确认继续保留。遇验证码由用户完成，访问仍受限时保留诊断并报告未通过，不假造实站成功。
- 移除 DEFAULT_TOPPs_PROFILE.verified、空验证白名单或“未完成现场验收”形成的全局启动阻断。随程序提供可维护的实际页面及来源规则；用户明确开始后运行到具体步骤检查，缺字段/未知来源/访问失败时提示该步骤错误或人工处理，不能一开始封锁所有试用。
- 实现真实信用卡 iframe 流程：识别对应主页面或独立 iframe、核对来源、切换并填入、确认字段状态、恢复主页面、单次提交。测试必须把卡字段放入多个独立/跨源 iframe，覆盖缺失、重建、异常来源及银行验证，不能只在父页面放假字段代表完成。
- 软件显示当前版本并提供主动检查更新：从固定 HTTPS 发布源查询新版/说明，打开可信下载入口，由用户运行新版安装器覆盖安装。升级前结束任务并退出，保留配置、profile、驱动及全部未决记录，失败可恢复；不做后台静默更新。
- 完成标准为相应代码、受控回归、Windows 安装/升级演练及试用说明。真实登录、真实购买和付款结果仅作为用户可选试用记录，不再是启动、开发完成或归档硬前置。

## Capabilities

### New Capabilities

- `purchase-targets`: 直链/关键词简单入口、单一指定目标、可选预设复用、数量和 USD 预算。
- `task-execution`: 默认人工登录与可试用入口、持续库存等待、可证明未加购的重试、停止和结果记录。
- `topps-checkout`: 按步骤核验的官方流程、逐次加购、独立支付 iframe 填写、默认配送与单次付款恢复。
- `local-settings`: 可选登录资料及必需付款本地资料、运行状态展示、旧窗口配置兼容、隐私和升级保留。
- `windows-installation`: UC 浏览器基线、动态版本匹配、驱动暂存处理/验证/启用、自动/手动准备、Windows 分发及便捷更新。

### Modified Capabilities

无。正式主规格尚未归档。

## Impact

- 本轮仅修改规划、项目规则及任务，不改源码、依赖锁、真实资料、外层 ERP 或免责声明 README。已有自动登录/UC/下单代码和测试记录保留，但未覆盖的付款 iframe、全局启动阻断及审查发现的重试/超时问题重新待办。
- 不以开发者真实账号、信用卡扣款或官网实际成交作为开发交付条件，也不能把未实测说成成功。取消全局阻断不等于删除实际步骤的来源、数量、预算和未决状态检查。
- Windows 安装和覆盖升级仍需实际构建及受控环境验收；更新源在对用户发布时需配置固定有效 HTTPS 入口，开发测试可使用受控响应，未配置时应明确显示而非假报最新。
- 不扩展到抽签、拍卖、批量账户/多目标付款、手机、小程序、其他站点、API 直连或后台常驻更新服务。真实试用与后续速度优化由用户另行安排。
