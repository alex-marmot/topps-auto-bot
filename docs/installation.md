# 安装与驱动维护

## macOS Apple Silicon 试用包

在 Apple Silicon Mac 上解压 `ToppsAutoBot-<版本>-macos-arm64.zip`，打开其中的 `ToppsAutoBot.app`。使用前安装 Google Chrome，并在应用的“驱动”页准备匹配的 ChromeDriver。应用内含 Python 和 Tcl/Tk。

试用包使用 ad-hoc 签名，尚未经过 Apple 公证。在其他 Mac 上下载并打开时，Gatekeeper 可能会拦截。

## Windows 安装前准备

- Windows 10/11 x64。
- 已安装 Google Chrome（推荐使用官方稳定版）。不需要另外安装 Python、开发工具或命令行组件。
- 首次启动需要网络访问 Chrome for Testing 官方元数据与下载地址；也可以在有网络的机器上下载驱动后手动选择。

安装包为当前用户级安装：不要求管理员权限，程序文件与用户数据分离，通常安装到当前用户的应用目录。安装完成后可打开初始化向导。

## 获取 Windows 安装包

正式发布后，在项目的 GitHub Release 的 **Assets** 下载 `ToppsAutoBot-Setup-<版本>.exe` 和同名 `.exe.sha256`。可用 PowerShell 的 `Get-FileHash -Algorithm SHA256` 核对安装包。软件内打开的 Pages 下载说明页会链接到具体版本的 Release。

## 首次启动

1. 从开始菜单打开 `Topps Auto Bot`，进入“驱动”页检测 Chrome。可以选择现有 Chrome 可执行文件。
2. 使用自动下载或手动导入准备驱动。准备完成后，点击“打开专用 Chrome（无需购买资料）”，在窗口中人工登录。
3. 按 [设置说明](settings.md) 保存收货、信用卡和预算，再按 [使用流程](usage.md) 选定一个商品及数量。

## 浏览器启动：UC、Chrome 与专用 profile

购买会话使用 Selenium + `undetected-chromedriver`（UC）启动正常可见 Chrome，显式传入已检测的 Chrome 和已验证受管理驱动路径，复用本程序专用持久化 profile，不读取日常浏览器资料。初始参数包含 `--disable-blink-features=AutomationControlled`、`--start-maximized`、`page_load_strategy='normal'` 和 `use_subprocess=True`，UC `version_main` 来自当前检测版本，不写死 146/156。上述方案不保证通过 Cloudflare；普通 Selenium 仅作为明确标识的对照诊断。

默认保留 Chrome 沙箱，并向 UC 显式传入 `no_sandbox=False`。只有针对可复现兼容问题，用户才可在设置页开启关闭沙箱的诊断选项；改变参数后需要重新验证，不能因 403 自动关闭沙箱。

## 驱动准备：暂存、验证、启用

自动下载和手动选择都遵循同一流程：

1. **私有暂存**：自动模式下载到 `driver-staging/<操作标识>/`，手动模式把选定的 `chromedriver.exe` 复制到同类暂存目录。暂存副本不是已启用驱动。
2. **完整验证**：检查同一份副本的平台、版本与当前 Chrome 主版本，先对同一副本执行 UC 处理，再通过实际 UC 启动、关闭独立空白浏览器。版本号匹配或文件复制成功都不算验证完成；运行阶段不得再隐式下载或修改活动驱动。
3. **原子启用**：验证通过后把副本晋升到 `drivers/`，再保存有效驱动选择。保存失败时旧驱动和旧选择保持；未完成启用的副本不用于购买。

空白验证使用临时 profile 和当前选定的沙箱参数。首次使用旧版本保留的驱动选择时，如缺少验证摘要，请在驱动页重新准备。

### 自动下载

- 只使用 Chrome for Testing 官方 HTTPS 元数据和下载地址。
- 按检测到的 Chrome 版本选择兼容驱动，不写死某个 Chrome 主版本，不使用任意镜像兜底。
- 显示版本、下载阶段和进度；没有可靠总大小时只显示已下载字节数或阶段，不伪造百分比。
- 下载、解压和验证都可以取消。

### 下载中取消并手动选择

1. 点击“取消下载，改为手动选择”。
2. 该操作的启用权限被撤销，后台连接终止，未完成文件清理；已启用旧驱动保留。取消后的迟到结果不会覆盖手动选择。
3. 从 Chrome for Testing 官方页面下载与当前 Chrome 主版本匹配的驱动并解压。
4. 在向导中选中解压后的 `chromedriver.exe`。程序只复制并验证副本，不修改原文件，也不会联网补下载。

### 验证或启用失败

- 显示失败阶段和原因，提供重试、手动选择或稍后处理入口，不无限自动重试。
- 新驱动失败不会删除旧驱动；但旧驱动仍需通过当前 Chrome 兼容性检查才能继续使用。
- 完整验证后、启用提交前取消会清理暂存副本，不改变有效选择。
- 若启用已经提交后收到迟到取消，界面显示已完成，不误报取消。

## 每次任务前的检查

开始任务前，程序重新检测 Chrome 并检查已启用驱动的路径、平台、版本和 SHA-256。Chrome 更新导致手动驱动失配时，任务不能开始；除非用户主动选择自动模式，否则不会自动下载或替换。任务执行、商品观察、加购、结算或本人验证期间禁止更换浏览器和驱动，修改只影响后续任务。

## 检查更新与覆盖安装

1. 在“关于”查看当前版本并主动点击“检查更新”。发现新版时，界面显示版本和发行说明，可用默认浏览器打开下载入口。开发包未设置发布源时显示“未配置发布源”。
2. 点击 Stop 并等待任务退出，关闭专用浏览器和应用，再运行下载的新版安装器。安装器发现旧程序仍在运行时会提示正常退出。待核对的加购或付款记录可以留在磁盘上。
3. 选择原安装位置进行覆盖。配置、专用 profile、已启用驱动及全部加购和付款记录位于独立的 `%LOCALAPPDATA%\ToppsAutoBot\`。新版启动后重新核实浏览器环境。未决记录仍按 [恢复说明](payment-recovery.md) 处理。

### 失败、回退与卸载

覆盖失败或取消后，先确认应用已正常退出，再用之前保留的安装器覆盖原安装路径恢复程序文件。保留现有用户数据目录，尤其是最新的 `run-state.json`。回退遇到不兼容的配置或记录格式时，使用支持该格式的版本恢复访问。升级和回退不会自动开始旧任务。

卸载默认保留本地资料。只有主动确认清除才删除程序的用户数据目录。清除前先处理未决动作。自行安装的 Chrome 和原始手动下载的驱动在程序数据目录之外。

## 本机验证记录

开发环境（macOS，不是 Windows 验收）：

- CPython 3.14.0 + Tk 8.6 可创建并销毁 Tk 窗口。
- Chrome 156.0.8078.80。
- Chrome for Testing ChromeDriver 156.0.8078.80。
- UC 3.5.5 已加入锁定依赖；macOS 上对 UC 处理后的暂存驱动重新做 ad-hoc 签名后，受控空白启动和本地全流程通过；Windows 和实站组合尚未验收。
- 官方元数据查询、下载、平台/版本检查、空白浏览器启动关闭验证均通过。
- 用户级 Windows 安装、无 Python 环境启动、升级/卸载演练尚未完成；不能把 macOS 或本地模拟结果当作 Windows 安装验收。

Windows CI、首次发布和 Pages 清单恢复步骤见 [开发与测试](development.md)。
